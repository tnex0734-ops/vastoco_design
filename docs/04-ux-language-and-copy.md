# UX language and content rules

## Voice

Clear, reassuring, professional and human. Keep sentences short. Prefer concrete verbs over promotional jargon. Explain what happens next.

## Canonical terminology

| Concept | Use | Avoid mixing with |
|---|---|---|
| Audience one | Client | Customer / homeowner as role label |
| Audience two | Professional | Vendor / seller / provider |
| Find service providers | Find a professional | Discover talent |
| Account creation | Create account | Register / sign up interchangeably |
| Existing account | Sign in | Login / log in interchangeably |
| Public work page | Professional profile | Seller page |
| Work samples | Projects / portfolio | Gallery for all contexts |
| Paid session | Video consultation | Call / appointment / meeting interchangeably |
| Cost to client | Consultation fee | Charges / pricing without context |
| Client-facing project info | Project details | Client brief (reserved for professional-side context) |
| Credential review | Verification | Certification / background check unless verified by policy |

## CTA language

- Client primary: **Find a professional**.
- Client secondary: **For professionals** / **Join Vastoco** as context requires.
- Professional primary: **Join Vastoco**.
- Professional secondary: **For clients**.
- Generic signup prompt: **How would you like to use Vastoco?**
- Avoid identity-first wording such as “Who are you?”; explain the user's goal.

## Role selection rules

- Don't show a blocking role popup at first page entry.
- Let visitors understand the platform and browse public discovery content first.
- If intent is known through the CTA or route, carry the role forward and skip the role selector.
- Ask the role only when someone chooses a generic Create account action without context.
- Allow role switching or adding another role only if Vastoco confirms that the account system supports it.

## Form writing

- Keep a visible label on every field.
- Use helper text to explain why a project or credential detail is requested.
- Clearly distinguish required and optional fields.
- Preserve valid entries after validation errors.
- Explain how to fix an error; don't use vague “invalid input” messages.
- Don't ask for payment details or sensitive credential documents in this static prototype. Passwords may be entered only in the clearly labelled demo authentication form; never persist or transmit them.
- For uploads, show file type and size limits before the selection.

## Trust language

- Say “Verification pending” until the review is actually complete.
- Explain that architects have a COA check because the brief explicitly says so.
- The current official professional page also describes identity plus qualification or documented-practice checks for interior designers and Vastu consultants. Keep this sourced as current product-page context and recheck before release.
- Show consultation fees before payment.
- Only show reviews eligible under Vastoco's real-consultation review policy.
- Never claim guaranteed clients or guaranteed income.
- State the 85% share as a fee split, not an income guarantee.

## Sample data

This prototype uses “Sample profile”, “Illustrative profile” and placeholder text where inventory would appear. Never use fictional profile names, ratings, review counts, partner logos or project statistics as if they are real.
