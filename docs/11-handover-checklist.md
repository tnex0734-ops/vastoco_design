# Handover checklist

## Design
- [ ] Both public homepages reviewed at 1440px and 390px.
- [ ] Root gateway is clearly supplementary and does not replace either official door.
- [ ] Both homepages visibly link to the other door.
- [ ] Client and professional CTAs have distinct intent.
- [ ] All placeholder data is visibly labelled.
- [ ] The supplied Vastoco wordmark geometry is preserved in the required monochrome Espresso treatment.
- [ ] Runtime UI, logo and illustrations use only Espresso (`#3C2415`) and Pale Oak (`#DDD9CE`); source-only inspiration images are clearly separated.
- [ ] Image/icon/font licences are documented.

## UX
- [ ] Client can explore before account creation.
- [ ] Signup role is only asked when intent is unknown.
- [ ] Existing user sees sign-in rather than duplicate account creation.
- [ ] Booking flow shows duration, budget, scope and timeline before confirmation.
- [ ] Fee is visible before payment; no invented fee is shown.
- [ ] Professional verification explicitly calls out the COA check for architects.
- [ ] Pending verification is not shown as complete.
- [ ] Professional setup can be reviewed before publishing.

## Engineering
- [ ] `npm test` passes.
- [ ] `npm run build` passes.
- [ ] No horizontal overflow at 390px.
- [ ] Keyboard navigation and focus indicators work.
- [ ] Reduced motion is respected.
- [ ] No console errors or missing assets.
- [ ] No real credentials or payment details are collected in the demo.

## Submission
- [ ] PDF opens and is readable outside the team.
- [ ] Confirm the PDF handover meets the organiser's Figma/PDF requirement.
- [ ] Record a 2–3 minute walkthrough.
- [ ] Include team name and team member information in the submission email.
- [ ] Include registration reference from the payment receipt.
- [ ] Check all links open outside the team.
- [ ] Submit one email to info@vastoco.in before the deadline.
